# Agent Note: 外部 Session 展示历史

Status: implemented

[English](2026-11-09-external-session-display-history.md) | 中文

## 问题

外部代理引擎可以拥有执行与对话历史，而 Harness 提供 Chat 界面。把这些历史复制进原生 Session 会创建另一份持久转录。原生历史游标、模型请求及重建保证也会看起来在描述 Harness 引擎从未执行过的数据。

较早页面的插入也与原生仅追加日志冲突。通过替换 Session 扩展历史会改变本地身份，而且不能安全地绕过活跃工作、停放输入或结果不确定的确认。

## 决定

Session Controller 提供归 effect 生命周期所有的外部历史注册表。提供方被动解析 Harness Session 地址，并提供展示分页、观察及独立的冷态 Agent 激活。生成的 `sessionHistory` Remote 服务先按目标 Session 授权，再解析提供方。它承载不透明的数据源游标与 generation，独立于原生 control 和元数据投影游标。

Client 选择一个历史 driver，通过现有 Conversation assembly 发布其有序窗口。外部记录是展示事实，不是原生 Session 日志，也不是模型执行证据。数据源自己的 Definition 渲染它们。追加与补丁帧保留已经加载的较早历史；替换明确重置窗口。权威的输入回执会移除本地回显，无需匹配消息文本或创建历史。

普通 Agent 解析器先尝试外部激活，再读取原生持久化。并发调用共享归提供方所有的激活过程；取消某个调用只会放弃该调用的等待。原生日志操作拒绝已经被外部认领的身份。提供方失败不会转到原生历史。移除提供方会取消并等待读取、激活和上游迭代器释放，不停止其引擎。已知认领在同一次 Host 生命周期内保持不可用；重启后，提供方从自己的持久元数据恢复所有权。

[原生插件记录决策](2026-08-30-retain-ignorable-external-session-events.zh.md)仍负责原生追加和重载。[Client 引用决策](2026-09-15-client-session-references.zh.md)仍负责保留；这两个独立的决定都没有被外部展示数据源取代。

## 考虑过的替代方案

**把投影副本持久化为原生消息。** 不采用，因为外部引擎仍然是权威来源，而重复转录会让人误以为存在实际上没有的原生重建保证。

**每次加载较早页面都创建另一个原生 Session。** 不采用，因为只读分页也需要替换本地身份、待处理工作与阅读锚点，而且转录仍然会被持久复制。

**绕过控制器修改 Client 的事件源。** 不采用，因为分页状态、日志截点、重连策略与 Conversation 窗口会分别归不同 owner 管理。注册的 driver 让它们遵循同一个生命周期。

## 结果

原生 Session 保留现有日志与 SDK 操作。自定义 Client 载体需要新的发现命名空间，非 owner 策略必须明确授权这些操作。原生 Session 格式不变。外部适配器仍负责自己的引擎持久化及重置检测；当后端没有可靠的 revision 时，注册表不会虚构一个。

Host 测试覆盖被动发现、不透明分页、调用提供方前的权限检查、无需原生读取的激活、调用方独立取消、提供方移除、认领歧义、原生委派与原生位置操作拒绝。真实的 Loader profile 组合生产 Gateway、外部历史服务和假的后端提供方；包内展示快照记录分页与补丁，不挂载 Session 持久化或推理。Client 测试覆盖 driver 选择、分页、补丁与重置一致性、回执及断开连接。此机制不提供精确轨迹重建或递归外部 subagent 所有权。
